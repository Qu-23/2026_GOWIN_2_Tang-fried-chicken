# ACG525 接入状态

确认目标接口为 Mega 60K 底板上标识 CH569 USB3 的 Type-C 插口。
目标通路为 ACG525 → USB → CH569 → HSPI → FPGA。现有 V14 UART 通路独立于 CH569。

## 原理图核对

随包 `mega60k_dock_sch.pdf` 为 Tang_Mega_60K_Dock(NEO)，图纸 Rev 1.4，日期 2025-03-31；实际板修订号仍需与实物匹配。

- 第 5 页框图：USB3.0 Type-C → CH569 → 16 位 HSPI → FPGA。
- 第 20 页：CH569 USB-C Connector 为 P1，数据差分线经过切换/保护电路接至 CH569。
- 第 21 页：CH569 为 U12，HD[15:0] 及 HSPI 控制信号连接 FPGA；CH569_Debug_UART 另接 TP18/TP19。

因此 CH569 的 Type-C 不是普通 TTL UART 接收脚。它也不是目前 CST 中 V14 的 USB-UART 通路；两者不能互换。

## 当前代码

| 通路 | FPGA 端口/引脚 | 当前支持 |
| --- | --- | --- |
| 现有有线演奏输入 | uart_rx / V14 | A5 四字节二进制帧 |
| JDY-31 接收 | uart_bt / B15 | 二进制帧及 N/O、S/K/P/X 文本 |
| JDY-31 回传 | uart_bt_tx / B16 | 演奏事件等回传 |
| CH569 Type-C | 需通过 CH569 与 HSPI | 本提交包尚未接入 |

引脚表来自当前实现的 CST 和布线报告。B15/B16 已用于蓝牙。不得把 USB 差分线、CH569 调试 UART 或其他已有功能网络当作空闲 RX。

## USB 方案需确认

1. ACG525 一侧的具体 USB 控制器及主机能力。目前尚未拿到该侧 USB Host 实现、端点或驱动资料。
2. CH569 板载固件的版本与 USB 描述符。不能假定其出厂行为就是 CDC 虚拟串口；需先枚举确认设备类、VID/PID、接口和端点。
3. 明确谁承担 USB 主机、谁承担设备；两个 USB 设备端不能仅靠 Type-C 线自行通信。连接供电和端口角色需同时核对。
4. 明确 CH569 的数据接口协议和固件来源，验证 USB 接收后能通过 HSPI 向 FPGA 输出数据；如需改 CH569 固件，应另保存原固件/恢复方法。
5. FPGA 接收 HSPI 数据后，可复用现有 A5 命令解析协议；但仍需实现 HSPI 接收、跨时钟缓存、帧边界恢复及与蓝牙事件的仲裁。

音符命令所需带宽较低，USB 速率由两端控制器和固件共同确定。
当前包不含 CH569 固件及 HSPI 接收 RTL；ACG525→CH569→FPGA 通路尚未实现。
